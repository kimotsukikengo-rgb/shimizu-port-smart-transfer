2. システム全体像

清水港に寄港するクルーズ船の乗客（主に外国人観光客）向けに、タクシーチャーター観光ツアーの予約・販売・配車・運行管理・実績集計を一気通貫で行うWebシステム。

現状の課題: 紙ベースの受注管理、手書きの運行指示書、Excelでの集計 → これらを統合的なWebシステムで効率化。

4つのフロントエンドアプリケーション

3. 機能スコープ

📱 URL A: 顧客予約サイト（7画面）

  • 5言語対応（英・日・中・韓・西）
  • コース一覧・詳細・行程表示
  • 予約フォーム（顧客情報・人数・船名）
  • 旅行条件書（旅行業法対応）
  • Stripeクレジットカード決済（海外カード対応）
  • 予約確認メール（PDF添付）
  • モバイルファースト設計

🏪 URL B: スタッフ端末（14画面・5ロール）

  • 営業: 受注入力（特記事項・オプション3行・ドロップオフ）
  • 決済: 4種決済（mPOS/全旅/現金/Web）・W番号入力
  • 配車: 車両ごと配車・指示書PDF・LINE/WhatsApp送信
  • 受注修正: 決済前の内容変更
  • 乗務員: ワンタイムURL・延長/返金・原価5項目・顧客満足度
  • 役割選択UI、タッチ操作最適化

📊 Admin: 管理画面（11画面）

  • ダッシュボード（取扱高/仕入/粗利/粗利率/帰着待ち/運行完了）
  • 受注一覧（13カラム・CSV出力・未入力チェック）
  • 配車管理
  • 運行指示書PDF（プレビュー・印刷・送信）
  • ワンウェイ記録
  • 運行実績管理・売上集計
  • マスタ管理4種（コース・車両・乗務員・スタッフ）

📈 分析: 寄港管理・業務分析（7画面）

  • 寄港情報登録（5セクション: 基本情報・W番号・当日情報・公式ツアー・シャトルバス）
  • 業務分析ダッシュボード
  • クルーズ船ランキング（前年比）
  • 人気ツアー分析
  • タクシー会社ランキング
  • 天気×売上分析
  • クルーズ船マスタ

6. 法令対応・コンプライアンス

旅行業法対応（募集型企画旅行）

  • 旅行条件書の事前交付: 予約前に提示し、明示的同意を取得（電磁的方法）
  • 取消料規定の明示: 7日前/3-6日前/1-2日前/当日の段階的取消料
  • 旅行業務取扱管理者の明示: サイト上に記載
  • 運行指示書の保管: 帳票として5年間保管義務
  • 行政報告: 国土交通省への定期報告（CSV/PDF出力で対応）

個人情報保護・セキュリティ

  • 個人情報保護法（日本）+ GDPR配慮（外国人個人情報）
  • HTTPS全ページ、SSL/TLS必須
  • カード情報サーバー非保持（Stripeトークン化）、PCI DSS SAQ A-EP準拠
  • ロールベースアクセス制御（RBAC）
  • SQL Injection / XSS / CSRF 対策
  • ワンタイムURL（乗務員報告、署名付きトークン、当日有効期限）

7. 開発フェーズ

Phase 1: 基盤構築 (最優先)

  • DB設計・マスタデータ投入（13テーブル）
  • 認証基盤（スタッフログイン、JWT）
  • 寄港情報登録（Admin、5セクション）
  • マスタ管理（コース・タクシー会社・車両・乗務員・スタッフ・公式ツアー）

Phase 2: 当日業務 (最優先)

  • URL B 受注入力（特記事項・オプション・ドロップオフ）
  • URL B 決済処理（4種決済、W番号車両単位）
  • URL B 配車入力（車両ごと）・受注修正
  • Admin ダッシュボード（粗利率含む5カード）・受注一覧
  • Admin ワンウェイ記録・売上集計
  • 運行指示書PDF生成（車両ごと、特記事項2種類）

Phase 3: 顧客予約 (重要)

  • URL A 全7画面（予約フロー）
  • Stripe決済連携（海外カード・3Dセキュア）
  • 予約確認メール + PDF添付
  • 多言語対応（5言語）

Phase 4: 通知・連携 (重要)

  • 乗務員 運行完了報告（ワンタイムURL、延長/返金、原価、顧客満足度）
  • LINE送信（乗務員グループ）
  • WhatsApp送信（顧客通知）
  • メール送信（運行指示書）

Phase 5: 分析・レポート (後続)

  • 業務分析ダッシュボード
  • クルーズ船ランキング・人気ツアー分析・タクシー会社分析
  • 天気×売上分析
  • CSV出力 / 行政レポート

8. 業務フロー（一気通貫）

① 事前準備（前日〜数日前）

寄港情報登録 → 船名・入出港時刻・W番号枠を設定 → 公式ツアー紐付け → 事前予約受付（URL A）

② 当日（受注〜決済）

営業がURL Bで受注入力 → 受付番号 自動発行 → 決済デスクで受付番号確認 → 内容確認（修正可） → mPOS/全旅/現金/Web決済 → W番号入力（車両ごと）

③ 当日（配車〜出発）

配車担当が車両・乗務員引当 → 運行指示書PDF生成（車両ごと） → 乗務員にLINE/メール送信

④ 運行中〜完了

乗務員がツアー実施 → 乗務員がスマホで運行完了報告（行き先・帰着時刻・延長/返金・原価・顧客満足度） → 管理画面で実績確認・集計 → 行政レポート出力

10. 非機能要件

項目要件
可用性寄港日 朝6時〜夜8時の安定稼働。ダウンは業務に致命的
応答速度受注入力 1秒以内、決済 3秒以内、分析画面 5秒以内
同時接続当日業務 最大15名（営業5+決済2+配車2+管理2+予備）。URL A 同時50セッション
データ保持受注データ5年間（旅行業法）、分析データ過去3年分
バックアップ日次自動バックアップ、30日間保持
ブラウザ対応Chrome/Safari/Edge最新版（IE非対応）
通信環境清水港の通信不安定環境への配慮（PWA・オフライン入力検討）
